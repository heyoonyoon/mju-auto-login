# 명지대 자동 로그인 (MJU Auto Login)

명지대 LMS, MSI 같은 통합로그인(SSO) 사이트에 로그아웃 상태로 들어가면, 크롬에 저장된 계정으로 알아서 로그인하고 원래 보려던 사이트로 돌려보내는 크롬 확장 프로그램입니다.
클릭도 지문도 필요 없고, 확장 프로그램은 비밀번호를 저장하지 않습니다.

## 사용 방법

### 1. 크롬 설정

1. 명지대 통합로그인(`sso.mju.ac.kr`)에 한 번 직접 로그인하고, 크롬이 비밀번호 저장을 물으면 **저장**합니다.
   - `sso.mju.ac.kr`에 저장된 계정이 **하나**여야 합니다. 여러 개면 크롬이 어느 계정을 줄지 몰라서 동작하지 않습니다.
2. `chrome://password-manager/settings`에서
   - **자동으로 로그인**: 켬
   - **비밀번호 입력 시 화면 잠금 사용**: 끔 (켜져 있으면 크롬이 계정을 넘겨주지 않습니다)

### 2. 설치

아직 크롬 웹 스토어에 올리지 않아서, 지금은 직접 설치해야 합니다.

1. 이 저장소를 내려받습니다. (`Code` → `Download ZIP` 후 압축 해제, 또는 `git clone`)
2. `chrome://extensions`에서 오른쪽 위 **개발자 모드**를 켭니다.
3. **압축해제된 확장 프로그램 로드**를 누르고 내려받은 폴더를 고릅니다.

### 3. 사용

그냥 LMS나 MSI에 들어가면 됩니다. 로그아웃 상태면 1~2초 안에 로그인된 화면이 뜹니다.

자동 로그인이 실패하면 화면 위에 빨간 안내줄이 뜨고 자동 로그인이 멈춥니다. 직접 로그인한 뒤 안내줄의 **자동 로그인 다시 켜기**를 누르면 됩니다.

---

## 불편했던 점

- 명지대 LMS는 브라우저를 껐다 켜면 항상 로그아웃되어 있다.
- 다시 들어가려면 매번 `통합로그인 서비스` 클릭 → 아이디/비밀번호 자동 완성(지문 인증) → `로그인` 클릭 → 비밀번호 변경 안내 화면에서 `취소` 클릭을 거쳐야 한다.
- 특히 비밀번호 변경 안내는 로그인할 때마다 뜨고, 매번 취소를 눌러야 한다.
- 강의 하나 보려고 들어갈 때마다 이 과정을 반복한다.

## 문제 정의

> 로그아웃 상태로 명지대 사이트에 들어갔을 때, 사람이 하던 로그인 과정을 **사람 손 없이** 끝내고 원래 사이트로 돌아가게 한다.

조건:

- 클릭도, 지문도 없이 전부 자동일 것
- 비밀번호를 확장 프로그램 안에 **평문으로 저장하지 않을 것**
- 설치는 **확장 프로그램 하나**로 끝날 것 (별도 앱 설치 X)
- 비밀번호든 무엇이든 외부 서버로 보내지 않을 것
- 비밀번호가 틀렸을 때 계속 재시도해서 계정이 잠기는 일이 없을 것

## 해결 과정

### 1. 왜 로그아웃되는지 확인

로그인 과정을 브라우저 개발자도구로 기록(HAR)해서 분석했다.

- LMS의 로그인 쿠키(`JSESSIONID`)는 만료 시각이 없는 **세션 쿠키**라서, 브라우저를 끄면 사라진다.
- 로그인은 OAuth 2.0 인가 코드 방식과 같은 모양이다.
  LMS → SSO 로그인 화면 → 아이디/비밀번호 제출 → 비밀번호 변경 안내 → (취소) → LMS로 돌아옴.
- 비밀번호는 SSO 페이지의 자바스크립트가 **제출하는 순간 암호화**해서 보낸다.
  → 암호화를 따라 만들지 말고, 칸에 값을 넣고 페이지의 로그인 버튼을 그대로 누르기로 했다.

### 2. 비밀번호를 어디서 가져올까

가장 어려운 부분이었다. 검토하고 버린 방법들:

| 방법 | 버린 이유 |
|---|---|
| 확장 프로그램 저장소에 비밀번호 저장 | 평문 저장. 배포하면 더 부담 |
| 확장 프로그램 안에서 암호화해서 저장 | 암호를 푸는 열쇠도 같은 곳에 있어야 해서 실질적인 보호가 안 됨 |
| 패스키(WebAuthn)로 열쇠 만들기 | 매번 지문이 필요함 |
| 쿠키를 계속 살려두기 | 브라우저가 꺼져 있는 동안 서버 쪽 세션이 만료됨 |
| 맥 키체인 + 별도 프로그램 | 설치할 게 두 개가 됨 |

남은 방법은 **크롬 비밀번호 관리자에 이미 저장된 계정을 빌려 쓰는 것**이었다.
웹 표준인 Credential Management API를 쓰면 페이지가 크롬에게 저장된 계정을 달라고 요청할 수 있다.

```js
navigator.credentials.get({ password: true, mediation: "silent" })
```

`mediation: "silent"`는 "사용자에게 묻지 말고, 조용히 줄 수 있을 때만 달라"는 뜻이다.

### 3. 실제로 되는지 시험

코드를 쓰기 전에 SSO 로그인 화면의 개발자도구 콘솔에서 위 코드를 직접 실행해봤다.

1. 첫 시도: **안 줌** (`null`)
2. 원인 추적: 크롬 설정의 **비밀번호 입력 시 화면 잠금 사용**(Touch ID)이 켜져 있었다.
   지문 없이 비밀번호를 넘겨주면 이 설정의 의미가 없어지니, 크롬이 조용한 요청을 거절한 것으로 보인다.
3. 화면 잠금을 끄고 다시 시도: **받음**. 아이디와 비밀번호(길이만 확인)를 모두 받았다.

### 4. 확장 프로그램으로 만들기

사람이 하던 단계를 하나씩 코드로 옮겼다. (자세한 건 아래 [동작 원리](#동작-원리))

### 5. LMS 말고 다른 사이트도

처음엔 LMS에서 온 로그인만 처리했다. 그런데 명지대 사이트들은 같은 SSO를 쓰기 때문에, 조건을 "어느 명지대 사이트에서 왔든"으로 넓히자 MSI에서도 그대로 동작했다.

### 6. 명지대가 페이지를 바꿔도 버티게

처음엔 로그인 칸을 `#input-userId` 같은 **이름표**로 찾았다. 이름표가 바뀌면 바로 멈추는 구조다.
그래서 이름표로 못 찾으면 **페이지 구조**("비밀번호 칸이 하나 있는 폼, 그 앞의 글자 칸, 그 폼의 제출 버튼")로 찾게 바꿨다. 크롬 자동 완성이 칸을 찾는 방식과 비슷하다.

## 최종 해결법

- 비밀번호는 **크롬 비밀번호 관리자**에서 그때그때 받아서 쓴다. 확장 프로그램은 비밀번호를 저장하지 않는다.
- 로그인 화면에서 칸을 채우고 **페이지의 로그인 버튼을 그대로 누른다.** 암호화는 명지대 페이지가 원래대로 한다.
- 비밀번호 변경 안내는 취소 버튼이 이동하는 주소로 **바로 이동**해서 건너뛴다.
- 자동 제출 직후 로그인 화면이 다시 뜨면 **실패로 보고 멈춘다.**

## 동작 원리

확장 프로그램은 **content script**(특정 주소의 페이지가 열릴 때 크롬이 그 페이지 안에 끼워 넣어 실행하는 자바스크립트)로만 이뤄져 있다.
`manifest.json`에 "이 주소가 열리면 이 파일을 실행하라"를 적어두는 방식이다.

```
LMS/MSI 접속 (로그아웃 상태)
   │
   ├─ LMS: 로그인 화면(login_form.acl)        ── lms-login-form.js ──▶ sso_check.jsp 로 이동
   ├─ LMS: "접속이 종료" 알림창                ── lms-session-alert.js ─▶ 로그인 화면으로 이동
   └─ MSI 등: 바로 SSO로 이동
   ▼
SSO 로그인 화면 (sso.mju.ac.kr/sso/auth?client_id=...)
   │  sso.js: 크롬에서 계정 받기 → 칸 채우기 → 로그인 버튼 클릭
   ▼
비밀번호 변경 안내 (sso.mju.ac.kr/sso/change/pw?cm_cg_id=...)
   │  sso.js: /sso/auth?cm_cg_id=... 로 바로 이동 (= 취소 버튼과 같은 동작)
   ▼
SSO가 원래 사이트로 돌려보냄 → 로그인 완료
```

### 파일별 역할

| 파일 | 실행되는 곳 | 하는 일 |
|---|---|---|
| `src/lms-login-form.js` | LMS 로그인 화면 | SSO 로그인 흐름(`sso_check.jsp`)으로 보낸다. 1분 안에 계속 되돌아오면 무한 반복을 막기 위해 멈춘다. |
| `src/lms-session-alert.js` | LMS 전체 | 세션이 끊겼을 때 뜨는 "접속이 종료" 알림창만 가로채서 로그인 화면으로 보낸다. 다른 알림창은 그대로 띄운다. |
| `src/sso.js` | SSO 전체 | 로그인 화면에서 자동 로그인, 비밀번호 변경 안내 건너뛰기, 실패 감지. |

### 비밀번호 변경 안내를 건너뛰는 원리

취소 버튼의 코드는 결국 `/sso/auth?cm_cg_id=<주소에 있는 값>`으로 이동하는 게 전부다.
그래서 버튼을 누르는 대신, 주소에서 `cm_cg_id`를 읽어 그 주소로 바로 이동한다.
단, **확장 프로그램이 방금 자동 로그인한 경우에만** 건너뛴다. 사용자가 직접 비밀번호를 바꾸러 들어간 경우는 건드리지 않는다.

### 실패했을 때 멈추는 원리

자동으로 제출하기 직전에 제출 시각을 기록해둔다. 1분 안에 로그인 화면이 다시 뜨면 비밀번호가 틀린 것으로 보고, 실패 표시를 남긴 뒤 더 이상 시도하지 않는다.
틀린 비밀번호로 반복 시도하면 계정이 잠길 수 있기 때문이다. 실패 표시는 사용자가 **자동 로그인 다시 켜기**를 누를 때까지 유지된다.

### 왜 페이지 안(MAIN world)에서 실행하나

`sso.js`와 `lms-session-alert.js`는 페이지 자신의 자바스크립트와 같은 환경(`"world": "MAIN"`)에서 실행된다.

- `navigator.credentials.get`이 페이지에서 직접 호출한 것과 똑같이 동작하는 것이 확인됐다.
- 페이지의 `alert` 함수를 가로채려면 페이지와 같은 환경에 있어야 한다.

## 개인정보와 권한

- 비밀번호를 **저장하지 않는다.** 로그인할 때마다 크롬 비밀번호 관리자에서 받아 칸에 넣을 뿐이다.
- 저장하는 것은 SSO 페이지의 `localStorage`에 남기는 "마지막 자동 제출 시각"과 "실패 여부"뿐이다.
- 어떤 데이터도 외부로 보내지 않는다. 서버가 없다.
- 동작하는 주소는 `https://lms.mju.ac.kr/*`, `https://sso.mju.ac.kr/*` 두 곳뿐이고, 그 외 권한은 요청하지 않는다.

## 한계

- 크롬의 **비밀번호 입력 시 화면 잠금 사용**을 꺼야 한다.
- LMS에서 직접 로그아웃을 눌러도 곧바로 다시 로그인된다.
- LMS의 "접속이 종료" 알림창 가로채기는 아직 실제로 확인하지 못했다.
- 로그아웃 상태에서 바로 SSO로 보내지 않고 자체 로그인 화면을 먼저 띄우는 사이트는, LMS처럼 사이트별 처리를 따로 추가해야 한다.
- 명지대가 로그인을 여러 단계로 나누거나 2단계 인증을 추가하면 코드를 고쳐야 한다.
